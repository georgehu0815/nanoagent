## Understanding WhatsApp Identifiers

### 1. Direct Messages (Personal Chats)

**Format:** `<phone_number>@s.whatsapp.net`

**Examples:**
- Your account: `13522355298@s.whatsapp.net`
- Someone else: `14155551234@s.whatsapp.net` (if their number is +1-415-555-1234)
- International: `447700900123@s.whatsapp.net` (UK number: +44-7700-900123)

**Phone Number Format:**
- Remove all spaces, dashes, and formatting
- Include country code WITHOUT the `+`
- Examples:
  - +1 (415) 555-1234 → `14155551234`
  - +44 7700 900 123 → `447700900123`
  - +86 138 0013 8000 → `8613800138000`

### 2. Group Chats

**Format:** `<group_id>@g.us`

**Example:** `120363012345678901@g.us`

Group IDs are automatically generated by WhatsApp and look like random numbers.

## Sending Messages TO WhatsApp Users

### From Code (Tools)

If you want the agent to send a message to a specific WhatsApp user:

```python
from nanobot.bus.events import OutboundMessage
from nanobot.bus.queue import MessageBus

msg = OutboundMessage(
    channel="whatsapp",
    chat_id="14155551234@s.whatsapp.net",  # Full WhatsApp ID
    content="Hello from nanobot!"
)

await bus.publish_outbound(msg)
```

### From Cron Jobs

Schedule messages to specific WhatsApp users:

```bash
nanobot cron add \
  --name "morning_reminder" \
  --schedule "0 9 * * *" \
  --channel whatsapp \
  --to "14155551234@s.whatsapp.net" \
  --message "Good morning! Here's your daily summary."
```

## Troubleshooting Cron Jobs

### Problem: Cron job created but no messages received

**Common causes:**

#### 1. Missing `--deliver` flag ⚠️
The most common issue! Without `--deliver`, the job executes but doesn't send messages.

**Check:**
```bash
cat ~/.nanobot/cron/jobs.json | python3 -c "import json, sys; [print(f'{j[\"name\"]}: deliver={j[\"payload\"].get(\"deliver\")}') for j in json.load(sys.stdin)['jobs']]"
```

**Fix:** Remove and recreate job with `--deliver` flag:
```bash
nanobot cron remove JOB_ID
nanobot cron add --name "test" --every 3600 --channel telegram --to "YOUR_CHAT_ID" --message "Test" --deliver
```

#### 2. Gateway not running or missing environment variables

Cron jobs only execute when the gateway is running. For Azure OpenAI, the gateway needs credentials.

**Check gateway status:**
```bash
ps aux | grep "nanobot gateway" | grep -v grep
```

**Restart gateway with credentials (if using Azure OpenAI):**
```bash
pkill -f "nanobot gateway"
export AZURE_CLIENT_ID="your-client-id-here"
nanobot gateway --verbose > /tmp/nanobot.log 2>&1 &
```

**For Telegram, ensure token is in config:**
```bash
cat ~/.nanobot/config.json | jq '.channels.telegram'
```

#### 3. Wrong recipient format

- **Telegram:** Use numeric chat ID (e.g., `523504695`), not username
- **WhatsApp:** Use full format (e.g., `14155551234@s.whatsapp.net`)

**Find your Telegram chat ID:**
```bash
# Message your bot, then check logs
tail -100 /tmp/nanobot.log | grep "chat_id" | grep -v "DEBUG"
```

#### 4. Gateway started before job was created

The gateway loads jobs at startup. If you add a job while the gateway is running, restart it:

```bash
pkill -f "nanobot gateway"
export AZURE_CLIENT_ID="your-client-id-here"  # If using Azure
nanobot gateway --verbose > /tmp/nanobot.log 2>&1 &
```

#### 5. Manual vs. Automatic Execution

**Important distinction:**
- `nanobot cron run JOB_ID` - Runs outside gateway, messages won't be delivered
- Automatic execution - Gateway runs jobs and delivers messages

**To test properly:**
1. Ensure gateway is running
2. Wait for scheduled time
3. Check logs: `tail -50 /tmp/nanobot.log | grep "Cron:"`
